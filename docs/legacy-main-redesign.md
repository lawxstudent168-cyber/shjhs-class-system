# 從舊版 main 接續設計

基線：`abedul59/shjhs-class-system` 的 `main`，commit `c788f354cf2553dd721c2a5c44e4f3f4dd4854ed`。
備份：`lawxstudent168-cyber/shjhs-class-system` 的 `codex/progress-before-upstream-reset-2026-10-07`，保留原本 PR #1–#6 的進度。

這個分支只從備份中重用個人首頁與學生手機廣播的程式；導師今日待辦、舊裝置核准流程與其他先前功能不進入此分支。教室廣播仍使用原有的 IP／設備名稱設定，學生手機廣播改用獨立的身分綁定與收件匣。

## 流程

1. 學生在 `/personal` 驗證座號、生日與身分證後五碼。伺服器核對後，為這個網域的瀏覽器建立有期限的學生綁定。`localStorage` 中的姓名標籤不構成廣播權限。
2. 導師使用原有的台灣日期動態密碼登入 `/admin`，在「遠端廣播與定時」內選學生或全班，輸入文字後送出。送出成功代表收件資料已保存，與學生是否在線、已讀或聽見無關。
3. 學生再次開啟同一網站時，自動讀取未讀訊息；網頁在前景時定期更新。收到文字無須操作，提示音須先在瀏覽器按一次啟用；背景、關閉網頁與鎖屏不保證播放聲音。
4. 切換到家長身分、登出或解除綁定時停止學生音訊並撤銷此瀏覽器的廣播綁定。家長頁面不主動播放學生廣播。

## 驗收界線

- 驗證學生 A 後只可讀取 A 的未讀訊息；同一裝置改以家長身分登入後，不再收到學生廣播。
- 離線時先發送，重新開啟網頁後可補收 24 小時內的未讀文字；過期不再顯示。
- 未曾綁定的學生仍能先收件，首次驗證後補收；清除 Cookie 或更換網域須重新驗證。
- 系統只能驗證「此瀏覽器持有該學生憑證」，無法從網頁判定手機實際所有人。家長若用學生資料登入自己的手機，仍可能成為學生裝置；要保證物理上的家長手機絕對無聲，必須有額外的設備管理機制。

部署前依 `docs/student-broadcast.md` 設定 SQL 與 Vercel 環境變數。同一 Supabase 若已執行過 SQL，保留現有資料並跳過重跑；此分支本身沒有修改正式資料庫。
