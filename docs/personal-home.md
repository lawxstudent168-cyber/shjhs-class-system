# 學生／家長個人首頁

入口是 `/personal`。公共首頁的身分列與身分選擇視窗都有連結。

## 使用方式

- 學生：輸入座號、西元生日 8 碼、身分證後五碼。
- 家長：輸入孩子的上述資料，加上完整的已綁定 Email（`parents.email` 或 `students.parent_email`）。尚未綁定可前往原有家長綁定頁。
- 家長可按「驗證另一位孩子」，用同一 Email 逐一驗證最多 10 位孩子並切換。不同 Email 重新驗證會取代原有孩子清單；切換學生身分也會清除原有家長孩子清單。
- 座號必須在目前學生名單唯一；同座號多筆資料會拒絕驗證，避免誤選學生。
- 個人登入最長保留 8 小時。公共首頁原本的姓名身分標籤不會被當成個人首頁的登入憑證。

## 功能

- 作業：逾期、今天到期、待完成、已交與全部分類；遵守既有「不列入家長報表」排除設定。今天到期不算逾期，沒有期限仍算待完成。
- 今日與明日聯絡簿、班級注意事項。
- 班級公告；家長另可看家長公告及有效期間內的家長須知，遵守原有顯示開關。
- 最近 30 天導師訊息，家長與學生頻道分開。
- 家長可查看最近 30 天送出的請假通知，以及導師已讀／尚未讀取狀態。已讀不等於核准；保留學校書面請假流程。
- 最近 30 天出缺席紀錄。沒有紀錄不推定為缺席。
- 私訊導師、家長請假、公共看板捷徑；目的頁仍採既有驗證。

個人首頁不寄信、不修改作業、不標記私訊已讀，也不修改請假或出缺席。

## Vercel 部署

沿用既有 Supabase 環境變數，不需要新增資料表或 SQL migration。

**新增伺服器環境變數 `NUXT_PERSONAL_HOME_SECRET`**，至少 32 字元的隨機密鑰。建議在本機終端執行 `openssl rand -hex 32` 產生，再貼到 Vercel 的 Environment Variables，勾選實際使用的 Preview／Production 環境並重新部署。不要放到 `NUXT_PUBLIC_*`、GitHub 或前端程式碼。

缺少這個變數時，個人首頁 API 回傳 503，不會略過驗證。更換密鑰會讓既有個人登入失效。不同 Vercel 網域的 Cookie 各自獨立，可使用不同密鑰；資料仍可連同一個 Supabase。

新 API 使用目前 Supabase 模組的 server client 與現有 RLS 政策，不使用 service-role key、不修改 RLS。正式環境需確認現有角色可讀必要欄位；權限不足時顯示載入失敗，不能改成公開所有資料來解決。

## 驗證邊界

個人首頁伺服器核對既有生日／身分證尾碼，家長另核對已綁定 Email。簽章 Cookie 設為 HttpOnly、SameSite=Strict、正式環境 Secure。每個個人查詢都檢查簽章中的學生清單，再按學生 ID 和對話頻道查詢。私密 API 使用 `private, no-store`，敏感驗證欄位不回傳瀏覽器；公告以文字呈現且連結只允許 HTTP(S)。

本功能沒有把全站改成 Supabase Auth，也沒有修正舊頁面的前端驗證及直接資料存取。不能把新 API 的隔離解讀為整套舊系統已完成資料權限改造。生日與身分證尾碼仍屬既有知識式驗證，未來可獨立遷移為正式帳號或 Email OTP。

登入有每個執行個體的錯誤次數限制（同來源 IP／座號，15 分鐘最多 10 次），不具跨 Vercel instances 的共享限制；如需全域防護，可在 Vercel Firewall 為 `/api/personal-home/session` 配置 rate limiting。

## 測試與驗收

```sh
node --test tests/*.test.js
npm run build
node --test tests/personalHome.integration.mjs
```

整合測試啟動本機模擬 Supabase 與建置後的伺服器，測試錯誤憑證、私密資料隔離、孩子驗證／切換、家長／學生頻道、禁止跨站登出、Cookie 清除及無資料庫寫入。只使用虛構測試資料。

瀏覽器驗收：家長登入 → 作業篩選 → 驗證另一位孩子 → 切換孩子 → 登出 → 學生登入；確認學生看不到家長專用區，手機 390px 不水平溢出。部署後再以測試學生檢查正式 Supabase 欄位與 RLS；本機驗證未連線到正式 Supabase。
