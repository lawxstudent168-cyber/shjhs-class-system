# 家長與實名足跡追蹤中心

後台保留單一「家長與實名足跡追蹤（含全站紀錄）」入口，內含實名身分、每次登入／工作階段、訪客設備、全網站紀錄四種檢視。可按日期、姓名／角色、IP、操作、頁面或登入階段搜尋，逐批載入更多紀錄，匯出目前篩選的 CSV。全網站紀錄保留 IP 封鎖與解除封鎖功能。

統計以目前查詢範圍內已載入的紀錄計算，畫面顯示載入筆數與資料庫總筆數，不把每個點擊都算成一次登入。時間統一顯示為 Asia/Taipei。

## 資料與相容性

沿用 `visitor_logs` 的 `role`、`ip_address`、`device_info`、`action_details`、`created_at` 與 `id`，不需要新增資料表、欄位或執行資料庫遷移。新紀錄以 `@visitor/v1:` 前綴加 JSON 寫入 `action_details`，包含事件類別、身分與驗證來源、登入階段與瀏覽器設備識別、頁面路徑、操作說明及結果。舊資料仍可讀取，缺少身分或登入階段時顯示「未記錄」，不依 IP 回推姓名或合併登入。教室電腦監視器也會解析新格式。

瀏覽器設備識別是該網站 localStorage 中的隨機識別碼；清除網站資料、使用另一瀏覽器或另一網站網域會產生不同識別。舊紀錄只能使用 IP／User-Agent 推估設備，介面會標明。相同 IP 不代表相同的人。

一次成功的登入／身分驗證會建立新的工作階段。重新整理沿用階段，登出／鎖定會結束它；閒置超過 30 分鐘的後續活動另開延續階段，不增加登入次數。首頁記憶身分、既有登入狀態延續、本次重新驗證分開標示。導師等共用密碼只能識別角色；它不能證明是哪一位具名老師。

## 紀錄範圍

`app/plugins/visitor-tracker.client.js` 在 Nuxt 客戶端載入，記錄包含首頁在內的頁面進入、路由變更、按鈕點擊及選項變更。只記錄按鈕可見標籤或欄位名稱，不讀取密碼、表單內容、私訊內文、網址查詢參數。追蹤中心內部查詢控制不自動寫入點擊，避免檢視紀錄本身淹沒紀錄；IP 管理結果仍有明確事件。

主要驗證入口（首頁身分、點名／聯絡簿等密碼解鎖、導師後台、課表、座位、考試、衛生、風紀、作業、廣播、家長及學生私訊）會記錄登入角色及來源。登出與點名鎖定亦有獨立事件。

點名與私訊傳送會檢查資料庫回傳錯誤後再寫入「成功」結果；既有作業、聯絡簿及注意事項的功能稽核同步到此中心，標示為「功能回報」。其餘通用點擊／欄位變更只表示觸發動作，不表示儲存完成。新事件無法補回過去未曾記錄的操作。

這是瀏覽器回報的操作追蹤，不是伺服器端授權證據。沿用原本的資料表存取政策，不提升 anon 權限。若寫入被拒絕或斷線，主功能仍可繼續，瀏覽器會顯示追蹤寫入失敗警告；不能宣稱那段期間的紀錄完整。

## 驗證

執行 `node --test tests/*.test.*` 與 `npm run build`。`tests/visitorTracking.test.mjs` 驗證跨身分／登入階段隔離、共用 IP、同一瀏覽器 IP 變更、舊資料、搜尋、CSV、非同步身分快照及追蹤失敗不阻擋主要操作。


## 聯絡簿與其他功能的個人足跡

近期聯絡簿查詢頁在共用查詢密碼驗證後，優先沿用當前的具名學生／家長身分，其次才使用裝置記憶中的具名學生／家長身分。來源標示為既有身分關聯，不將共用密碼視為重新實名驗證；無法識別個人時記為「家長／學生（未具名）」，僅出現在全部紀錄／登入階段，不錯誤歸入實名個人清單。導師模式仍記為導師，不能把先前的導師角色借給家長查詢。

查詢成功會記錄日期範圍、查得幾日紀錄與結果，不複製聯絡簿事項。首頁聯絡簿資料載入完成、沒有編輯／驗證視窗遮擋，且至少 10% 的元件持續進入可視範圍 1 秒後，記為「內容顯示」，不是「已閱讀」。同一身分、登入階段、日期與本次頁面只記一次，背景刷新不累加；切換身分或新的登入階段會重新計算。頁面隱藏、捲出可視範圍、元件卸載會取消等待。未支援 IntersectionObserver 的瀏覽器只記主動操作，不推測可視範圍。

點選今日聯絡簿、某日歷史紀錄、班級注意事項、個人作業卡，會記錄功能名稱與日期等脈絡，不以整張卡片的內文作為紀錄。全站按鈕、連結、具按鈕／分頁角色的控制、展開摘要、選項變更、文字欄位取得焦點及表單提交也沿用當下身分與登入階段。觸控裝置的點選以 click 事件記錄，鍵盤啟動控制亦可記錄；不把單純滑動視為已閱讀，也不收集欄位值。
